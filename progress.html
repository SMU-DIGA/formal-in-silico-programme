The T4 claims are the soundness theorems of the certificate checkers (which run in exact rational arithmetic, so no floating point is involved) and the Frama-C/WP proofs about the trusted C kernel: no run-time errors, and, since 6 October, the floating-point correctness of its interval arithmetic under an IEEE 754 model (DFT-F01, F02). Of the two T0 claims, one is the DFT thread implementation (target T2); the other is CAL-I01, Lean’s definition of how a TDB file is read, which is a specification rather than a theorem and can only be cross-checked.

03

How a result earns its guarantee

The solver is never trusted. It proposes; a proved checker disposes. This is what lets us use LAPACK and fast floating-point code while still stating every output as a theorem. The same four steps run in every domain.

Untrusted · T0

Solver

A C driver runs the SCF loop, the FEM assembly, the Verlet integrator or the equilibrium search, and writes a certificate.

Data

Certificate

Floating-point numbers read as the exact binary rationals they are. Nothing in it is assumed to be correct.

Proved · Lean

Checker

Re-checks everything in exact rational arithmetic. Its soundness is a Lean theorem; a wrong certificate can only fail or widen the interval.

Guaranteed

Rigorous statement

An interval that provably contains the true quantity: the continuous FEM solution, the true MD trajectory, the global CALPHAD equilibrium.

Alongside, the DFT SCF controller is a TLA+ specification checked with TLC (it can report “converged” only if the residual is small, the gap is open and the certificate passes), and every run can emit a trace that is replayed against that specification.

On 6 October the checkers were reviewed adversarially, with the attacker in control of the certificate (and of the driver) but not of the checker or the command line. Seven flaws were fixed: phase names with Unicode line breaks or tabs that a script reading the output would split into forged lines and fields; huge decimal and binary exponents that hung a checker; a DOS printed although a k-point had failed or the weights did not sum to one; band labels that shifted after a failed k-point; and problem echoes (smearing, functional, grid) that were not all compared with the command line. None of the soundness theorems changed. Six weaker points are recorded for later, among them that a --tdb certificate may omit phases (they are listed as unsupported) and that a failed secondary check does not change the exit code. 62 forged certificates are replayed by make verify-all on every run.

05

What is trusted without proof

Every guarantee in every domain is conditional on this small, explicit base.

Lean 4The kernel that checks every proof; Mathlib, with only the three standard axioms
Lean compilerCompiles the checkers into executables, together with their input parsing (including reading a TDB file byte by byte) and decimal output (lower bounds rounded down, upper bounds up)
TLCThe TLA+ model checker
Frama-C / WPWith Why3, Alt-Ergo, CVC5 and Z3, for the run-time safety of the C kernel and, under WP’s IEEE 754 model, the floating-point correctness of its interval arithmetic; a contract for nextafter, libc contracts for sqrt, fabs, isfinite, and one admit for the value of INFINITY
C compilerUnverified for now; CompCert is an option for the trusted kernel
IEEE 754Only that round-to-nearest returns the nearest double; no error-size property is relied on

Each domain also has its own modelling conventions — for example that the certified problem uses the exact rationals written in the certificate, or that Lean’s definitions of the DFT external potentials and of how a TDB file is read say what the specifications intend — named on its page where they apply.

The C drivers that write those problems are untrusted, but they are kept honest. Their reports are checked line by line against the checkers’ own output. Their thread protocol is replayed against its TLA+ specification. They are fuzzed under AddressSanitizer and UBSan, and they reject any input they cannot write into a certificate exactly. Known-answer cases in every domain compare the checkers’ intervals with answers computed from the command line rather than the certificate, so a driver that solves the wrong problem is caught. All of this runs in make verify-all. Since 4 October the two largest gaps in how a certificate is tied to its problem are closed: the DFT checker verifies the external potential against its Lean definition, and the CALPHAD checker builds the model from the TDB file itself. The remaining problem data, such as the cell length, cutoff and temperature in DFT, are echoed exactly and compared with the command line, not recomputed. Since 5 October the DFT binding is mandatory: a certificate without it is rejected, and the archived certificates carry it. Since 6 October the parsers also refuse forged names and resource-exhausting numbers, and every DFT echo is compared (adversarial review).

06

Research results

Since 4 October the certificates are also used to answer questions that floating-point software cannot: that something does not happen, is global, or occurs more than once. Each result is archived with its certificates in the project’s research/ directory and re-checked by make verify-all.

Several exact Kohn–Sham solutions

A 1D LDA electron gas — four electrons per period, a cosine potential with a quarter of that period, Fermi–Dirac smearing — has at least five distinct exact solutions of its discrete SCF equations, proved by five SCF-solution certificates whose balls are disjoint. Their free-energy intervals also order them: the symmetric solution is not the lowest. A lower bound for one discrete problem, not a count. Details →

A certified audit of CALPHAD databases

316 binary systems from the 17 databases shipped with pycalphad, 246 650 grid points, every one certified against its TDB file. Five anomalous liquid miscibility gaps that open as the temperature rises, each bracketed to 1 K with proofs on both sides; a narrow fcc gap in Fe–Ni that pycalphad misses; in Cr–Ti, a Laves-phase equilibrium pycalphad misses by at least 9.8 kJ/mol; and a driver translation bug, now fixed.
