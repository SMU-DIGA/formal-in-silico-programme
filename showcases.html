01

How each result is made

Every case is a real run. The untrusted C driver computes a candidate solution and writes a certificate; the proved Lean checker re-checks the certificate in exact rational arithmetic and prints rigorous intervals and error bounds; then an established code in the field solves the same problem independently, and we check that its answer falls inside the Lean intervals.

Every number in a “Certified by Lean” table is printed by the checker, whose soundness theorem guarantees it for the problem the certificate describes (lower bounds rounded down, upper bounds up). The comparison with the reference code is supporting evidence only and is outside the chain of trust. Every archived certificate is re-checked by the current checkers in make verify-all.

Neumann at both ends: compatibility and the mean-zero normalization FEM

−u″ = e^{2x} on (0, 1) with u′(0) = 0, u′(1) = −(e² − 1)/2 (the decimal −3.194528049465325 on the command line), normalized by ∫u = 0. A solution exists only if ∫f + g₀ + g_L = 0; once the decimals are rounded to doubles this no longer holds exactly. The checker proves the defect c̄ to be about −9·10⁻¹⁷ (the interval excludes 0, so strictly the original problem has no solution) and certifies the precisely stated projected problem −u″ = e^{2x} − c̄. P1 elements, 24 cells; the discrete solution (the same as scikit-fem’s Lagrange-multiplier solution) differs from the true nodal values by one constant s, which the checker also encloses.
